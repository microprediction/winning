FAQ

Questions readers have actually asked about the methodology page, answered with the same rule the rest of the site follows: every number here is generated by a committed, seeded script, and where the honest answer is "open," it says so rather than hand-waving past it.

Why does the diagonal iteration beat Newton–Krylov, when the diagonal it preconditions with is exact, and diagonally preconditioned CG normally beats damped Jacobi on an SPD system?

Section 4 puts Newton–Krylov two orders of magnitude behind the damped coordinate iteration. But the slopes preconditioning that iteration are the Laplacian's own diagonal. Diagonally preconditioned CG beats damped Jacobi on an SPD system, so the ordering should flip — unless one Jacobian–vector product costs a lot more than one sweep. And separately: the page hedges that the per-iteration slope isn't quite the exact derivative — does that show up as bounded oscillation, or as growing error?

Two questions, and they have two different answers.

Why doesn't PCG's iteration-count advantage win on the clock?

It does have the advantage the intuition predicts — on iteration count. It loses on wall clock because of what each iteration costs. This was measured in three rounds (research/experiments/exp23_newton_cg), and the first two don't settle anything: round 1 runs unpreconditioned CG on raw share residuals, where tiny-share coordinates are invisible to both the residual and the Jacobian, so it pours the step into weakly determined tail directions and loses badly (387s, not converged, vs. 3.7s for the production sweep at \(n=200\)). Round 2 adds a diagonal preconditioner but keeps an only-approximately-symmetric Jacobian–vector product and no null-space projection, and diverges outright. Round 3 is the fair fight: a symmetrized log-residual Newton system, the exact integration-by-parts Jacobian–vector product (genuinely symmetric), the null vector projected out, and PCG preconditioned by the same own-log-slope diagonal the production sweep uses. That version is the first to converge at all, and on the easy case it reaches a residual an order of magnitude tighter than the diagonal iteration — at roughly sixty times the wall clock:

damped diagonal iteration0.5s9.2e-9converged
Newton–Krylov (round 3)29.7s9.6e-10converged

The reason is the cost per step, not the number of steps. The diagonal iteration's own-slope preconditioner is a byproduct of the forward pass it already has to run to get the shares — free. Each PCG iteration instead needs an exact Jacobian–vector product, which costs about one more full \(O(nL)\) field pass. The easy problem only needs a dozen of those in total, and it still loses on the clock, because the diagonal iteration's sweeps are each a fraction of a pass. So the flip the intuition predicts is real at the level of iterations; it just isn't the number that determines wall clock here.

Bounded chatter, or growing error?

The refresh point was right: because the diagonal iteration re-evaluates the field (and therefore the slope) every step, it is a fixed-point iteration, not a linearize-once-and-solve method, so an inexact slope only changes the rate of convergence, not where it converges to — the same reason Sinkhorn scaling converges under an approximate row/column normalization (the diagonal iteration is the hard-max analogue of exactly that construction).

Write the tie-density Laplacian as \(L = D - W\) (Section 3's \(J = -B^\top W_e B\), diagonal and off-diagonal parts). Jacobi splitting for \(Lv = r\) has sweep matrix \(M = D^{-1}W\). Because \(L\)'s rows sum to zero, \(D^{-1}W\) is exactly row-stochastic, so with the exact diagonal its spectrum sits in \([-1, 1]\) — the top eigenvalue is exactly 1, on the all-ones (gauge) direction that inversion projects out anyway, matching Section 4's remark that only ability contrasts are identified. On the contrast subspace, an eigenvalue can only reach \(-1\) in the degenerate limit of a bipartite tie-density graph — two clusters of contestants whose photo-finishes are almost all cross-cluster and almost never within-cluster. That is exactly a 2-dimensional race: two contestants, one edge, sweep matrix \([[0,1],[1,0]]\), spectrum \(\{+1,-1\}\) on the nose. So the diagnosis is right: with the exact diagonal an undamped sweep can only chatter (period-2, bounded), never grow: the eigenvalue reaching −1 is a geometry fact about how bipartite the tie structure is, not a symptom of an inexact derivative. Growth would need the diagonal to be underestimated, which pushes a contrast eigenvalue past −1.

Which one is actually seen, measured, is the honest place this answer has to stop being clean. On exp23's hard case (strong correlation, a small-cluster structure close to the bipartite limit above), the production diagonal iteration run alone stalls at a fixed residual (1.1e-4) against its iteration cap rather than diverging — bounded, consistent with the geometry story above rather than a growing-error one. But the same hard instance, run as the fallback sweep inside round 3's hybrid solver, does diverge (residual 6e+2) despite an accept-test that is supposed to reject a step that makes things worse. That divergence isn't yet cleanly attributed to either story; it's flagged as open in the experiment's own README and tracked as the next engineering item (Levenberg regularization and a fallback that's stable on the hard set), not swept into "just geometry."

Bounded chatter is the measured, explained behavior of the production sweep, including on the strongly correlated case that pushes closest to the bipartite limit. Growing error inside the Newton–Krylov hybrid's own fallback, on that same hard case, is measured but not yet explained — an open item, not a hidden one.
